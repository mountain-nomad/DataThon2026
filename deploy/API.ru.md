# API по разделу 10 ТЗ

Адрес: `https://cycle-ascertain-parsnip.ngrok-free.dev`.

API-ключ находится в `local/api_access.json` (поле `api_key`), а также в `backend/.env` (`API_KEY`). Это отдельный ключ сервиса: не пароль сайта, не токен GitHub и не токен ngrok. Ключ и адрес можно передать жюри. Файл с ключом исключён из Git.

Вход через браузер и cookie для API не нужны. Все запросы требуют заголовок `X-API-Key`.

```bash
BASE_URL='https://cycle-ascertain-parsnip.ngrok-free.dev'
API_KEY='<вставь api_key из local/api_access.json>'

curl --fail-with-body -sS "$BASE_URL/api/v1/analyze" \
  -H "X-API-Key: $API_KEY" \
  -H 'ngrok-skip-browser-warning: 1' \
  -F 'file=@/полный/путь/video.mov'
```

Ответ: `{"job_id":"..."}`. Затем запрашивайте статус примерно раз в 3–5 секунд, подставив полученный идентификатор:

```bash
JOB_ID='<job_id из ответа>'
curl --fail-with-body -sS "$BASE_URL/api/v1/jobs/$JOB_ID" \
  -H "X-API-Key: $API_KEY" \
  -H 'ngrok-skip-browser-warning: 1'
```

Пока модель работает: `{"job_id":"...","status":"processing"}`.

После завершения:

```json
{
  "job_id": "...",
  "status": "done",
  "verdict": "violation",
  "violations": [
    {
      "type": "Название типа нарушения",
      "timecode_sec": 12.4,
      "description": "Что видно на видео и почему это может быть нарушением",
      "evidence_frames": [
        {"timestamp_sec": 12.4, "image_base64": "...JPEG в base64..."}
      ]
    }
  ]
}
```

Без нарушений: `verdict=no_violation`, `violations=[]`. При ошибке: `status=failed` и `error`. Неверный или отсутствующий ключ возвращает HTTP 401.

Все модели и обработка видео работают локально. Одновременно обрабатывается одно видео; остальные ожидают. Сервер должен оставаться включённым, с запущенным ngrok. Заголовок `ngrok-skip-browser-warning` исключает промежуточную HTML-страницу ngrok из API-ответов.

ТЗ требует результат за 5 минут. Последний фактический запуск завершился за 175 секунд, но это не гарантия для длинных видео и очереди. Текущий серверный таймаут — 1800 секунд; сам по себе он не обеспечивает требование жюри о 5 минутах.

Локально используется тот же контракт по адресу `http://127.0.0.1:8000`, с тем же `X-API-Key`.

## Описание, ограничения и источники

В новых результатах `description` содержит наблюдение и связь со сценарным правилом, затем пустую строку и `Ограничения: ...`. Если rule_id сопоставлен с подходящей проверенной публичной нормой РК, далее идет пустая строка и `Источник: <документ>, <пункт> (<официальный URL>)`. В JSON эти переводы строк кодируются как `\n\n`; после разбора JSON это настоящие пустые строки. Если нормы нет, весь абзац источника отсутствует.

Названия `type` фиксированы по каталогу, а не сочиняются свободно. Проверка ограничивает структуру и соответствие идентификатору правила; она не доказывает фактическую правильность визуального наблюдения. Перечень норм и пробелов — [legal_mapping_review.md](legal_mapping_review.md).
