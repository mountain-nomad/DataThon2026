# Claude Code Prompt — Backend Implementation

## Project Context

У нас уже существуют:
- Готовый frontend.
- Готовый ML inference, находящийся в отдельной папке `ML`.  (на самом деле еще не готов просто нужно писать с асампшеном что он готов)
- VLM-модель, развернутая на RunPod и доступная через API endpoint. (бэкенд не должен самостоятельно обращаться к эндпойнту инференса, он только использует функцию)
- Файл `Requirements.md` — основной источник технических требований и API-контрактов.
- Файл `Backend Description.md` — текущая документация backend-архитектуры.

**Задача — разработать backend, который соединит существующий frontend, Supabase Storage и ML inference.**

## Architecture

Ожидаемый flow:

1. Frontend отправляет `.mov` видео через HTTP POST (`multipart/form-data`).
2. Backend принимает и валидирует видеофайл.
3. Backend загружает файл в Supabase Storage.
4. Supabase возвращает путь к сохраненному объекту.
5. Backend формирует URL для доступа к видео.
6. Backend возвращает frontend информацию о загруженном видео.
7. В дальнейшем backend будет вызывать функцию из папки `ML`, передавая необходимые промпты и видео.
8. ML-функция обращается к RunPod endpoint, на котором работает VLM-модель.

## Current Priority — Phase 1

**Реализовать рабочий процесс загрузки видео через POST в Supabase Storage.**

### Backend requirements

- Реализуй или адаптируй существующий POST endpoint для загрузки `.mov` видео.
- Используй `multipart/form-data`, где видео передается через поле `file`.
- Проверь формат видео, размер и корректность запроса согласно `Requirements.md`.
- Загружай полученное видео в Supabase Storage.
- Генерируй уникальное имя/путь файла, чтобы избежать коллизий.
- Возвращай frontend идентификатор видео, путь к объекту и URL, по которому можно получить видео.
- Для приватного bucket используй signed URL. Сохраняй стабильный storage path, поскольку signed URL имеет срок действия.
- Не раскрывай Supabase service role key на frontend.
- Добавь корректную обработку ошибок загрузки, валидации и ошибок Supabase.
- Не требуй от frontend предварительной загрузки в объектное хранилище: файл должен приниматься непосредственно backend через POST.

### Existing architecture constraints

- **Не изменяй frontend.**
- **Не переписывай существующий ML inference.**
- ML inference остается отдельной функцией внутри папки `ML`.
- Эта функция должна получать необходимые промпты и видео и взаимодействовать с RunPod endpoint.
- Сейчас основной приоритет — загрузка и хранение видео, а не изменение логики VLM.
- Не добавляй лишние сервисы, очереди или инфраструктуру, если они не требуются для текущей реализации.

## Expected Result

В конце реализации должен работать следующий сценарий:

1. Клиент отправляет `.mov` файл через POST.
2. Backend получает видео.
3. Видео успешно сохраняется в Supabase Storage.
4. Backend возвращает корректный ответ с идентификатором и доступным URL.
5. Клиент может получить загруженное видео по возвращенному URL с учетом политики доступа bucket.
